# work-report — 会话工作交付

把当前 DeepSeek Harness 会话整理成可以直接交出去的正式文档:工作日报、周报、交接文档或公众号文章。文档会带上可验证的凭据块(报告哈希 + 产物哈希),让汇报有据可查。

## 何时使用

用户说"写日报 / 今天干了什么 / 周报 / 交接文档 / 交接说明 / 整理成公众号文章 / 写个总结"等要求时,使用本技能。

## 流程

1. **确认类型**:daily(日报)、weekly(周报)、handoff(交接文档)、article(公众号文章);拿不准就问用户一句。
2. **生成草稿**:调用 `report_generate` 工具,传入 kind;需要自定义标题时传 `title`。
3. **填充草稿**:把草稿中所有 `[[待写:…]]` 标记替换为真实内容。事实只允许来自:本次会话对话、草稿中的数据段、你通过文件/终端工具实际观察到的产物。**禁止编造**数字、文件、完成度——凭据块会记录哈希,虚报会被验证戳穿。
4. **保存**:调用 `report_save`:
   - `content` 传完整最终稿(不含凭据块,工具会自动追加);
   - `artifacts` 传你实际产出的文件路径列表(可空);
   - `path` 省略时自动存到 `reports/` 目录。
5. **回复用户**:保存路径 + 一句话摘要 + 报告哈希前 8 位。

## 各类型要点

- **daily**:围绕"今天做了什么、产出什么、问题是什么、明天做什么";数据段如实呈现,不美化。
- **weekly**:把本周诉求逐条小结完成度;突出关键数字(回合/步骤/Token/产出文件数);下周计划标注优先级。
- **handoff**:必须让接手人"不复盘会话也能继续":关键决策、未完成项、复现命令、坑位提示,一个都不能少。
- **article**:公众号风格——短段落(每段 ≤3 行)、口语化、开头钩子、金句、结尾互动;发表前删除"事实素材"一节。

## 硬规则

- 保存前检查:所有 `[[待写:…]]` 已替换,零残留。
- `path` 只能落在工作区内;工具会拒绝逃逸路径。
- 报告内容不得与凭据块矛盾(例如凭据显示 0 产物时正文不得声称"交付了 5 个文件")。
- 一次会话多次汇报时,每次都用最新的 `report_generate` 数据,不要复用旧草稿。
